# V1.6 Label Recovery Experiment (2026-02-28 and 2026-03-01)

Updated: 2026-03-02

## Goal

Test whether additional image analysis can recover pot IDs better from the weak-photo runs on:

- 2026-02-28
- 2026-03-01

without relying only on continuity mapping.

## Data and Ground Truth

- Source labeled intake: `data/intake/google_photos/manual_mixed_photos_labeled_v3.csv`
- Target runs analyzed: `2026-02-28`, `2026-03-01` (`64` rows total)
- Ground-truth pot IDs were taken from the current continuity-resolved mapping pipeline.
- Baseline visual templates were taken from run `2026-02-27` (the stronger baseline run).

python3 scripts/v16_ocr_recovery_experiment.py \
  --run-dates 2026-02-28,2026-03-01 \
  --visual-baseline-run-date 2026-02-27

## Results

### OCR variant recovery (pot number exact match)

Best single variant:

- `label_adaptive_psm6`: `4/64` (`6.25%`)

Union of all OCR variants per row:

- `6/64` (`9.38%`)

Summary source: `ocr_variant_ranked_summary.csv`.

### Visual similarity recovery (non-OCR)

Using 2026-02-27 baseline templates:

- top-1 pot match: `4/64` (`6.25%`)
- top-3 pot match: `7/64` (`10.94%`)

Summary source: `visual_similarity_summary.csv`.

### Combined interpretation

Both extra CV tracks are still weak on these two runs. They are not reliable enough for autonomous pot ID assignment.

## What This Means

1. The bottleneck is image capture quality and framing consistency, not just OCR algorithm choice.
2. Continuity mapping remains necessary for stable operation right now.
3. A low-effort human-in-the-loop lane is required for long-term robustness.

## Minimum-Effort Improvement Plan

1. Keep continuity-first mapping as production default.
2. Use the generated manual queue (`58` hard rows out of `64`) for targeted correction only.
3. Add a lightweight capture protocol for future runs:
   - keep one-pot framing,
   - keep pot tag in lower-center of frame,
   - avoid heavy motion blur,
   - keep photo long-side above `1500px` when possible.
4. Store corrected hard rows as supervised training data and iterate detector/OCR models in batches.
