# Garden CV Project - Research Agent Briefing

Last updated: 2026-03-02

## Core Research Hypothesis

"Can unstructured, everyday photos be converted into a consistent time-series record for individual plants without static hardware?"

## Section 0: Current Production Architecture and Known Risks

### Current 3-layer pipeline

#### Layer 1 - Intake and Baseline Mapping
- Pulls latest Google Photos batch.
- Builds per-run pot mapping (`1T`-`32T`) using continuity-first rules.
- Canonical series-to-variety map is fixed from one-time packet-name phase.

#### Layer 2 - Auto Identification (best effort)
Priority stack (high to low):
1. Manual pot overrides
2. Baseline pot continuity
3. Series/history fallback
4. Sequence inference for watering-day runs

OCR/CV tries to read pot/number cues from each photo. Continuity reconciliation stabilizes IDs across runs even when OCR is weak.

#### Layer 3 - Human in the Loop for hard rows
- For weak runs (currently `2026-02-28` and `2026-03-01`), generates a queue of uncertain rows.
- Reviewer page `/hard-row-reviewer` shows label/center/full crops.
- Reviewer confirms or corrects pot and variety, exports reviewed CSV.
- Corrections feed back into mapping/overrides and experiments rerun to measure uplift.

### What is working well
- Priority degradation stack has fallback paths.
- Triaging by run quality then row confidence keeps human effort proportional.
- Corrections as CSV gives auditability.
- Three-crop reviewer view is directionally correct.

### Live system findings observed on 2026-03-02

#### Finding 1: OCR has zero matches across all 58 queued rows
Every queued row shows `OCR Match Variants: 0`. This is complete OCR identity failure on the queue.

#### Finding 2: All 58 suggestions are sequence inference
Suggested pots are continuity/sequence placeholders, not evidence-based assignments.

#### Finding 3: Hard queue is not surfacing hard cases; it is surfacing complete failures
UI currently gives identical visual weight to evidence-backed vs zero-evidence suggestions.

#### Finding 4: OCR reads ambient numbers, not pot labels
Detected numbers likely come from background text, shelf numbers, or overlays. Crop landing zone is likely wrong.

#### Finding 5: Reviewer lacks an honest "cannot verify" state
Current verdict set lacks explicit "No basis - cannot verify from this photo".

### Known risks and design tensions

#### Risk 1: OCR crop targeting is wrong
Most urgent upstream issue.

#### Risk 2: Continuity is only signal and unvalidated
Current identity may be silently wrong.

#### Risk 3: Confident framing of zero-evidence suggestions hurts trust
Reviewers may rubber-stamp placeholders.

#### Risk 4: Hard queue may not represent total error
Confident continuity mistakes may bypass queue.

#### Risk 5: Manual feedback loop does not scale
Current CSV cycle is acceptable for tens of rows, not sustained growth.

### Core design tension
System intended as OCR-primary plus continuity fallback is currently operating as continuity-only with broken OCR and misleading confidence framing.

### Immediate diagnostic questions
1. Why is OCR Match Variants zero for all rows?
2. What do label crops actually show?
3. What numbers is OCR detecting, and where in photo are they?

## Experiments

### Type 0 - Live diagnosis (run first)

#### SW-0: OCR Crop Targeting Diagnosis
Type: 0
Decision: Why zero OCR matches? Crop target issue vs label absence vs OCR engine failure.
Urgency: Critical.

Steps:
1. Pull label crops for 10 hard-queue rows.
2. Inspect whether crops show stake/label region or not.
3. Cross-reference OCR numbers with visible regions.
4. Check full crops for same rows.
5. If labels visible in full but absent in label crop, crop targeting is wrong.
6. If labels absent in full crops, OCR is not viable for these photos.

Output: Root-cause classification.

#### SW-0b: Reviewer Signal Quality Audit
Type: 0
Decision: Minimum reviewer UX changes before further review effort.

Steps:
1. Classify all 58 rows:
- Type I: OCR match supports suggestion.
- Type II: OCR numbers exist but none match suggestion.
- Type III: OCR Match Variants 0 (sequence-only placeholder).
2. Count type distribution.
3. Quantify % of queue that is zero-evidence placeholders.
4. Define minimum UX fixes:
- signal-quality badge
- explicit "No basis" verdict
- group by signal quality tiers

Expected based on live data: approximately 100% Type III.

### Type A - Architecture validation

#### SW-1: Silent Error Rate Audit
Type: A
Prerequisite: SW-0 root cause known and crop-targeting fix applied if needed.
Decision: whether continuity can be trusted.

Steps:
1. Select 20-30 known-ground-truth photos.
2. Run full pipeline with human review disabled.
3. Count surfaced vs silent continuity errors.
4. Log continuity override decisions and correctness.

Metric: % of total errors that are silent.

#### SW-2: Sequence Inference Validation
Type: A
Decision: keep/demote/remove sequence inference.

Steps:
1. Extract runs where sequence inference decided mapping.
2. Compare against SW-1 ground truth.
3. Measure sequence consistency and error rate when sequence varies.

Metrics: consistency rate and error rate under inconsistency.
